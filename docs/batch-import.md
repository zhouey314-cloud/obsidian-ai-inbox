# 离线批量导入 Markdown / TXT / 明确结构的 JSON

在当前仓库目录运行 `python3 batch_import.py`（Python 3.9+，仅标准库；Mac / Linux）。
现有桌面收件窗口仍保留原来的 12 个附件限制；批量入口是独立命令，不依赖桌面安装器。
本功能只导入主动指定的本地文件，不访问账号、网络、剪贴板或其他目录。

## 先预览，再执行

先把你选择的导出材料放在一个**库外目录**，例如 `~/Documents/selected-exports`。
不要把整个 Documents、主目录或 Vault 根目录当作输入。
Vault 必须已经有 `.obsidian/`、`00 Inbox/raw/`、`04 Content/X/`；本工具不会创建或整理这些目录。

```bash
# 1. 预览：只读所选源文件和现有收件笔记；不会写 Vault
python3 batch_import.py preview \
  --vault '/path/to/existing-vault' \
  --source-type chatgpt \
  --plan '/path/to/import-plan-001.json' \
  '/path/to/selected-exports'

# 2. 打开 import-plan-001.json，核对 vault、files、来源、时间、错误和 preview 字段
#    preview 为 new / duplicate_existing / duplicate_in_batch；该清单不含正文

# 3. 明确执行该清单；报告文件必须是库外尚不存在的新文件
python3 batch_import.py apply \
  --vault '/path/to/existing-vault' \
  --plan '/path/to/import-plan-001.json' \
  --report '/path/to/import-report-001.jsonl'
```

示例中的路径都需要替换为你的真实路径；不要直接照抄 `/path/to/…`。
可一次指定多个文件或目录。目录默认只读第一层；**只有添加 `--recursive` 才递归所选目录**。
递归会跳过隐藏目录、`.obsidian`、`.git`、`node_modules`、`附件` 等现有排除目录和软链接目录。
隐藏文件不读取；发现软链接文件、未知扩展名或无法解码的文件，会列为错误，不读取其指向的内容。
显式选择隐藏路径、软链接路径、与 Vault 重叠的目录会停止预览。

来源用 `--source-type chatgpt / codex / meeting / other` 统一标记。
Markdown 和 TXT 是“用户自行导出的文本”，不会根据文件名猜测真实来源。
一份文本文件生成一篇收件笔记；不尝试按聊天回合拆分或自动总结。

## 支持什么格式

| 输入 | 行为 |
| --- | --- |
| `.md` / `.markdown` / `.txt` | 原文完整放入新收件笔记，不解析或重写正文、Markdown frontmatter |
| `.json` | 只接受下述 `obsidian-ai-inbox/v1` 结构；逐记录校验，坏记录隔离 |
| 其他格式、原生聊天树、JSONL、ZIP | 报告不支持；不会猜结构，也不解压 |

默认接受 UTF-8（可带 BOM）或带 BOM 的 UTF-16。GB18030 文本需要在预览时明确添加
`--encoding gb18030`，不盲猜编码；不能解码、含二进制控制字符的文件会报错。
Markdown 链接和附件引用保留原文，**不会复制引用目标、修复相对链接或保证导入后链接仍可用**。
源文件不会被移动、删除或修改。导入的是文本，不是原始文件附件的完整归档。

## 明确结构的 JSON：合成示例

```json
{
  "schema": "obsidian-ai-inbox/v1",
  "records": [
    {
      "id": "synthetic-chat-001",
      "title": "合成示例：RAG 排错讨论",
      "text": "用户：为什么没有召回？\n助手：先检查索引与过滤条件。",
      "source_type": "chatgpt",
      "source": "synthetic export; not a real conversation",
      "created_at": "2026-10-27T10:30:00+08:00",
      "updated_at": "2026-10-27T11:00:00+08:00"
    },
    {
      "id": "synthetic-project-001",
      "title": "合成示例：Codex 项目记录",
      "text": "实现接口并运行合成测试；尚未部署。",
      "source_type": "codex"
    },
    {
      "text": "合成会议转写：下周再确认负责人。",
      "source_type": "meeting"
    }
  ]
}
```

顶层仅允许 `schema`、`records`。每条记录必须有非空字符串 `text`；可选字段仅为
`id`、`title`、`source_type`、`source`、`created_at`、`updated_at`。
省略 `source_type` 时使用命令行选定的来源；省略 `title` 时使用源文件名。
时间需要带时区的 ISO 8601 字符串，保留原始表示；不会把文件修改时间当成对话创建时间。
未知字段、重复 JSON 键、重复记录 ID、非有限数字、空记录集或不明格式都会报告错误。
同文件重复 ID 的记录全部跳过，不擅自选择其中一份；其余有效记录可继续。

这是一种统一导入约定，**不是 ChatGPT / Codex 官方导出格式适配器**。
没有真实导出样本时，不转换原生历史、聊天分支、工具结果或附件，也不声称全量迁移成功。
如果你已有 Markdown / TXT 导出，可直接导入；其他 JSON 应先核对真实结构，再另行编写有测试的转换器。

## 来源、时间、哈希和增量规则

新笔记仍保存在既有 `00 Inbox/raw/`。复用 `Vault.capture()` / `_save()` 的进程锁、
独占创建、磁盘刷新、读回核对和完整性标记；没有新增数据库或第二套笔记存储。
原有 `created` 表示本次落盘时间；新增 `import_metadata` 保存：

- 来源类型、完整源文件路径、文件原始字节 SHA-256、文件大小、文件修改时间及纳秒值。
- 记录索引、可选原始 ID、标题、来源说明、可选原始创建/修改时间。
- 解码后的原文 SHA-256、正文 UTF-8 字节数和导入去重指纹。

去重身份是 **来源类型 + 原文 UTF-8 SHA-256**；不因改名、导出文件时间或记录 ID 改变而重复创建。
同文不同来源类型保留各自笔记；不同空格、换行或正文会被视为不同版本，追加新笔记。
标题、ID 或来源时间单独改变时不会新建笔记。重复记录的新增来源记录在本次报告中，已有笔记保持不变。
只复用完整且未被修改的本导入工具笔记；旧笔记被人工编辑或写入未完成时，追加新副本。
不拿库中任意相似文本做推断去重，也不合并此前通过普通收件窗口保存的材料。

同一批次可以重复执行（每次用新的报告文件名）；已完成项会作为 `duplicate` 返回。
有新导出或源文件变化时，应重新生成预览清单。执行时逐文件重新核对路径、文件哈希、
修改时间及派生记录元数据；与预览不符的整个文件标记 `changed`，不导入该文件。
预览中的去重预测可能因其他收件进程写入而变化；执行结果以共享进程锁内的检查为准。

## 报告、错误和中断恢复

计划与报告必须保存在明确指定的库外新文件中，不覆盖旧报告或任何源文件。
文件以权限 `0600` 创建。它们不包含正文，但包含文件路径、标题、来源和时间等私密元数据，
请留在本机，不提交 GitHub。

报告为逐行 JSON（JSONL）：第一行 `start` 含计划哈希与目标库，随后每条 `record` / `file`
列出成功、重复、错误或变化，最后一行 `summary` 汇总数量。成功和重复项均包含笔记相对路径及笔记哈希，
可据此打开笔记、核对来源与完整性。空批次会生成零项报告，不代表扫描了其他目录。
汇总的 `imported` / `duplicate` 按记录计数，`changed` 按文件计数；`error` 包含文件级及记录级失败，
具体单位与范围以各行的 `event` 和 `path` / `index` 为准。

每行报告都会刷新到磁盘。单个文件/记录失败不会阻断其余项；报告写入失败则立即停止，
避免继续执行却没有审计记录。没有 `summary` 的报告表示本次未正常结束，最后一行也可能不完整。
没有多文件事务：断电可能在“笔记已落盘、结果尚未记入报告”之间发生，也可能留下不完整的新笔记。
不要删除旧资料或盲目回滚；保留源文件和部分报告，核对后用相同计划及新报告名重试，或重新预览变化文件。
已经完整落盘的笔记会通过原有完整性校验去重；不完整的新笔记保留待人工核查。

退出码：预览成功为 `0`（仍需检查清单中的逐项错误）；执行成功为 `0`；
执行完成但有错误/变化为 `2`；全局校验或报告失败为 `1`。

每批最多 1000 个文件、10000 条记录；单源文件 25MB，每条原文 2MB，计划文件 32MB。
超限请按你选择的范围拆批。去重沿用现有目录扫描，对很大的收件目录可能较慢；不承诺实时吞吐。
不建立后台任务，不运行 AI，不改 `.obsidian`、原笔记、原目录布局或同步设置。
既有 Obsidian/iCloud 等同步行为属于其他软件，本工具不会更改它们。
